# 检测逻辑

本文依据仓库当前使用的 `lmfpd-sdk 0.2.0` 实现及 `web/src/store.js`、`web/src/detector.js` 编写。检测算法、参考库及校准参数来自 SDK 上游；本项目不重新训练检测器。依赖升级后应重新核对本文。

## 一次检测的过程

1. 用户选择配置和模型。模型列表由 Worker 请求上游 `/models` 获得，列表中的名称只用于指定请求目标，不作为模型身份的证明。
2. 浏览器调用 `loadDetector()`，优先经 `/api/data/` 下载参考数据，失败后尝试 SDK 默认来源。Worker 参考数据代理在边缘缓存 24 小时；SDK 使用浏览器内存适配层缓存，不使用本地磁盘。
3. SDK 默认生成三个随机挑战：每份要求输出 1 至 355 范围内的整数，数量在 292 至 332 之间，同轮目标数量不同。提示词语言及表达随机选取。
4. 使用选定的 Chat Completions、Responses 或 Anthropic Messages 协议请求模型，默认流式、每模型三份样本并行。跨域请求经 Worker 转发，评分仍在浏览器执行。
5. SDK 解析回答、检查样本、计算候选排名；应用显示结果并异步写入账户历史。历史写入失败不会使已经完成的检测失效。

应用默认同时检测 10 个模型，可设为 1 至 20。每模型内另有三个采样请求，所以理论采样并发约为模型并发的三倍。应用为每模型设置 180 秒总超时，主动停止会中止正在运行的任务。超时、取消及上游错误不代表模型身份。

## 数字解析与严格模式

`parseNumbers` 从文本中提取数字，保留 1 至 355 的值；遇到含字母的分隔文本时切分序列，取最长一段。它并非验证任意文本格式的通用解析器。

实时采样和已有文本分析都使用 `max(80, ceil(expected_count × 0.55))` 的最低数字数量门槛；实时采样还需满足响应正常完成等条件。目标数量不是必须精确达到的接受门槛。

宽松模式达到目标数量后会截取所需数字，并可提前停止接收回答，样本可能标记为 `truncated`；允许仅用一至两份成功样本给出部分排名。严格模式不进行该提前截取，并要求三份采样全部成功；它仍使用上述最低数量门槛，不保证每份数字数量与目标精确相等。

## 形态筛查与候选排序

评分前先检查相邻数字自相关和小步长比例。当前 SDK 满足 `autocorrelation <= -0.23` 或 `small_step_share <= 0.05` 时认为形态符合参考模型回答，否则返回 `not_model`，不生成排名。这只是统计筛查，不是对回答来源的确定判断。

候选排序综合以下信号：

- 数字频率：对 355 个整数的频次平滑，并提取 Hellinger 特征。
- 分段与参考距离：提取四段数字分布，与参考样本比对；频率分支结合线性判别、邻近参考距离及基线评分。
- 位置和序列：数字在序列中的位置、尾数、相邻转移、不同间隔的相关性等。

SDK 对各分支标准化，再按参考检测器中的权重融合排序。本项目直接采用 SDK 的排名结果，不以响应中的 `model` 名称替代评分，也不自行把相似分数换算为概率。

## 如何理解结果

| 字段 / 状态 | 含义 |
| --- | --- |
| `scored` | 三份有效样本产生完整排名；是否提供概率还取决于校准参数是否匹配 |
| `partial` | 一至两份有效样本产生部分排名，无校准概率 |
| `unscorable` | 不满足评分条件，不应解读为某模型匹配失败 |
| `not_model` | 数字形态未通过 SDK 筛查，不等于证明回答不是模型生成 |
| `ranking_score` | 用于候选排序的分数，不是百分比 |
| `probability` | 三份有效样本且校准参数匹配时的库内闭集相对概率，否则为空 |
| `probability_status` | `reference_calibrated` 表示有参考校准，`unavailable` 表示概率不可用 |
| `family_prediction` | 排名第一候选在参考库中的家族标签，不是独立身份验证 |

概率通过校准参数缩放排名分数后进行 softmax 得到，只在参考库列出的候选中归一化。**即使概率很高，也不能排除模型不在参考库内。** 模型版本、推理设置、上游路由及回答改写都可能影响结论；建议结合多次采样与其他证据判断。

## 可复现性与保存范围

SDK 默认参考源为 `https://lm.ikale.io/data/` 和 `https://cdn.jsdmirror.com/npm/lmfpd-data@latest/`。它们可能更新，提示词也随机生成，因此不同时间的结果不保证相同。当前账户历史只保存摘要、前三候选、样本状态及响应模型名等信息，不保留完整数字回答、全部挑战或完整参考版本元数据，无法仅靠历史记录重新计算原结果。
